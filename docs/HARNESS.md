# ハーネス設計

SameQは、「何を作るか」をプランナーが製品仕様書に落とし、ジェネレーターがスプリント単位で実装し、
エバリュエーターが実際にアプリを動かして合否判定する、3エージェント体制で開発されている。
さらにこの3者の受け渡しをオートループが無人で回すことで、全18スプリントの大半が夜間無人のまま
完走した。

## プランナー（Planner）

1〜4行程度のプロンプトを受け取り、詳細な製品仕様書に展開するエージェントです。

ポイントは、**技術的な実装詳細には踏み込まない**こと。仕様は「何を作るか」に集中し、「どう作るか」はジェネレーターに任せる設計です。

## ジェネレーター（Generator）

仕様書をもとに、検証可能な単位で実装を進めるエージェントです。

各スプリントの開始前に、エバリュエーターと「今回作る範囲」と「完了と判断する条件」を確認します。その合意に沿って実装し、スプリント終了時に自己評価を行った上で、エバリュエーターへ引き渡します。

## エバリュエーター（Evaluator）

Maestroでシミュレーターや実機上のアプリを操作したり、Chrome拡張機能などを通じてブラウザーを操作したりして、完成したアプリケーションを実際にテストするエージェントです。

UI操作だけでなく、必要に応じてAPIの応答やデータの保存状態も確認し、発見したバグ、仕様との差異、操作性の問題を具体的にフィードバックします。

データ消失や主要機能の不具合など、必須基準を1つでも満たさなければスプリントは不合格です。ジェネレーターはフィードバックをもとに修正し、再び評価を受けます。

## 起動時によく起きる2つの失敗（重要）

ジェネレーター（MiniMax-M3）はAnthropic純正モデルではなく、`ANTHROPIC_BASE_URL`と`ANTHROPIC_AUTH_TOKEN`を明示指定した互換エンドポイント経由でのみ到達できる。この制約から、起動方法を誤ると次の2パターンで必ず失敗する（2026-08-31、SameQ以外の複数プロジェクトで実際に再現・確認済み）。

1. **`Agent`ツールからの自動呼び出し** — `model_not_found`（HTTP 404）で即座に落ちる。Agentツール経由のサブエージェントは親セッションの特殊な環境変数を継承しないため。
2. **`!`プレフィックスや通常のBash呼び出しで`nohup ... &`** — ログファイルすら作られずに消える。ツール呼び出しが終わったタイミングでプロセスグループごと刈り取られてしまうため（`nohup`はSIGHUPからは守るが、この後始末までは防げない）。

**正しい起動方法**: コーディネーターが`Bash`ツールの`run_in_background: true`オプションに、`env ANTHROPIC_BASE_URL=... ANTHROPIC_AUTH_TOKEN="$MINIMAX_API_KEY" ... claude --agent generator -p "<指示>"`（`scripts/autoloop.sh`を起動する場合はそのコマンドそのもの）を`&`無しで直接渡す。これはハーネス自身がプロセスを追跡・デタッチする仕組みなので、ターンをまたいで生き続け、終了時に通知が来る。ユーザーが対話的にターミナルから起動する場合は`~/.local/bin/gen`ショートカット、またはそのフルコマンドで問題ない（この場合はシェルが正常に子プロセスを持つため上記の刈り取りは起きない）。

## オートループ（自動実行の仕組み）

プランナー・ジェネレーター・エバリュエーターの3エージェントを、人の判断を挟まずに自動で回し続ける仕組みです。

`state.json`という小さな状態ファイルが、いま誰の番かを管理します。ジェネレーターが実装を終えれば「評価待ち」に切り替わり、エバリュエーターが合格判定を出せば次のスプリントへ自動的に進む――この受け渡しをスクリプトが機械的に判断し、実装が動くたびにローカルへコミットを積み重ねていきます。人がやるのは、あとでログを読むことだけです。

エバリュエーターが**同じ理由で3回連続不合格**を出すと、そこでループは自動的に停止します。無限にリトライさせるのではなく、「これは人の判断が要る」というサインとして扱う設計です。

全18スプリント――匿名アカウント作成から、世界共通のお題、翻訳、通報・ブロック、サブスクリプション課金まで――は、この3エージェント構成で、実質ほぼ無人のまま完走しています。

## 止まるとき

オートループが止まるのは、基本的に「バグ」ではなく「安全装置」です。主に5パターンあります。

1. **完了して自動停止（正常終了）** — 全スプリントが`passed`になったら、そこで止まる。
2. **3回連続不合格で`blocked`** — 上述の3ストライクルール。実際、課金システムの実機検証では5回連続の差し戻しでこの仕組みが働き、開発者本人がサンドボックス購入を実行するまで一時停止した。
3. **タイムアウト／エラー終了** — generator・evaluatorには1回あたりの実行時間の上限がある。フル回帰テストが長引いて超えるとそこで停止する（実際に3時間タイムアウトが発生し、以降は回帰テストを絞り込む対策を入れた）。
4. **spec.mdに次のスプリントが無い** — 「仕様に無いものは作らない」原則があるので、続きが未定義だと自律的に停止する。
5. **ハーネスの手が届かない外部作業が必要** — generator/evaluatorはApp Store ConnectやSupabaseダッシュボードの認証コンテキストを持たない。人間（コーディネーター）が先に外側の設定を済ませてから引き渡す必要がある作業は、ハーネスだけでは完結しない。

つまり「止まる」の大半は「壊れた」ではなく「ここから先は人が決めて」という合図として設計されている。

## 実績

全18スプリントが完了し、App Storeへの審査提出まで到達している。
