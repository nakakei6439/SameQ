# いいねランキング → お題投稿権のカスケード（2026-08-30 ブレストメモ）

## 背景

SameQ の「今日のお題」は現状 `PromptGenerator` ＋ `prompt_lifecycle` SQL で
「48 件の候補プールから UTC 暦日ベースで選ぶ」だけ。LLM も Edge Function も
ない（sprint09 の見送り、migration 13 のコメント参照）。

ユーザー（Keita）からの 2026-08-30 夜の発言：

> 一番いい目をもらった人から順番に。なんかお題を投稿できるとかにしたら。
> お題投稿するのが楽になります。お題投稿してくれないか。
> いいねランキングみたいなのを作る。上から順番に。
> お題がなくなったらまたやるとかなんとか。

## 仮仕様（発言からの復元）

1. **ランキング**: 累計受信いいね数（received_like_count）で降順ソート
   - `posts.received_like_count` は spec F35 で既に集計あり
   - 同数なら `myPost.createdAt` の古参優先、みたいな tie-breaker
2. **投稿権**: ランキング上位 N 人（提案: 5〜10 人）が「今月のお題」を投稿できる
3. **サイクル**: 質問プールが尽きたら、1 位から順番に「お題投稿お願い」通知
   - 24h 応答なし → スキップして次へ
   - 全員スキップ → フォールバック（既存の UTC 日替わりプール）
4. **1 日の流れ**:
   - 8:00 JST: 「あなたの番です」通知 → 当日使うお題を 1 件投稿
   - 投稿締切: 翌 7:00 JST まで
   - 締切過ぎても未投稿 → 自動フォールバック

## 期待される効果

- **お題の多様化**: 候補プール 48 件の繰り返しではなく、コミュニティ発のお題が混ざる
- **エンゲージメントループ**: 高評価 = 投稿権 = 自分の声が今日の問いになる
- **F26（自動生成）の依存を脱却**: 仕様上は Edge Function で生成する話だったが、
  いまだ未実装（migration 13 の経緯）。人間キュレーションは「仕様の自然な実装」
- **スパム抑止**: 投稿権を得るハードル = 過去のいいね実績 → 悪意あるユーザーが
  量産しても評価されなければ投稿権を得られない

## 懸念（要仕様詰め）

1. **インセンティブ設計**: 「投稿する動機」が薄いかも？
   - 現状ユーザーは「答えるだけ」なので、「投稿する」は新しい行為
   - インセンティブ: 自分のニックネーム/絵文字がお題と一緒に表示？
   - 投稿したお題のいいね数に応じて投稿者のプロフィールが育つ？
2. **モデレーション**: 投稿されたお題は F17 / F18 / F19 / F20 の安全チェック必要
   - NG ワード / 個人攻撃 / 性的 / 政治 etc.
   - 自動判定 or 通報 → 一定数で自動非表示、moderator review
   - 既存 `safety_logs` / `posts_status` スキーマをどこまで流用できるか
3. **ゲーム化リスク**: いいねを買い占めて投稿権を得るチート
   - 既存 `rate_limiter` でブロック済みだが、本機能は「累計」が鍵なので
     短時間の連投で稼げない仕組みを再確認
4. **お題の重複**: 同じお題が複数の日に出ないようにする仕組み
   - 投稿時に「直近 30 日以内に出ていないか」チェック
5. **ランクイン/降格のタイミング**: 
   - 日次？週次？月次？
   - 1 位の人の気分が乗らない月もある → スキップが気軽にできるか
6. **新規ユーザーの体験**: いいね 0 の人は投稿権を得ない
   - 一定数（10 件とか）の回答をこなすと自動的に「最初の投稿権」を付与？
   - もしくはオンボーディングで 1 回は固定で投稿させる
7. **言語の整合性**: 英語 UI のテスターが英語のお題を投稿する動線
   - 既存 L10n は ja/en 切替のみ。投稿フォームに言語選択は要る？
