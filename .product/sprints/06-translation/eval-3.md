## 不合格の原因（これを直せば通る）

### [1]【最重要】端末に翻訳モデルが入っていない言語の回答に当たると、OSの「必要なダウンロード」シートが出てタイムラインが閉じ、二度と進まない

- **再現手順（実機・`-SameQFakeTranslate` なし）**:
  1. `-SameQResetState` で起動し、初回設定を終える
  2. 回答を投稿してタイムラインを開く
  3. 左スワイプを繰り返す
- **実際（4回中4回、必ず途中で止まる。乱数で順番が変わるので止まる位置はばらつく）**:

  | 実行 | 端末言語 | 読めた件数 | 止まった様子 |
  |---|---|---|---|
  | D01 (1回目) | ja | 5件 | 6件目が60秒出ない |
  | D01 (2回目) | ja | 6件 | 7件目が出ず、**OSの「翻訳／必要なダウンロード／ポーランド語・日本語」シート**が表示され、**タイムラインが閉じて今日のお題画面に戻る** |
  | D01 (3回目) | ja | 7件 | 8件目が出ない。シートは出ず、**タイムラインは開いたまま・カードも読み切り表示も無い空白**（`timeline.close=true` / `timeline.card.body=false`） |
  | D02 | en（`-AppleLanguages`） | 21件 | 22件目が出ず、**OSの「翻訳／必要なダウンロード／ポーランド語・英語 (アメリカ)」シート**が表示され、タイムラインが閉じる |

  いずれも **60秒＋追加30秒＝計90秒待っても復帰しない**（`固着から追加30秒待って復帰したか=false`）。
  アプリのプロセスは生きたままでクラッシュはしない。
- **期待**: spec.md 196行「スワイプすると次の翻訳可能な回答が表示される」、
  197行「翻訳モデルが端末に無い場合は**初回のみ準備中の表示**が出て完了後に読め」、
  199行「翻訳に失敗した回答は**エラーダイアログを出さず**、その回答をスキップして次を表示する」
- **根拠1（スクリーンショット）**: `.product/sprints/06-translation/eval-3-stall.png`。
  タイムラインが消えて今日のお題画面に戻り、その上にOSのシートが乗っている。
  シート内の文言（実測）:
  ```
  翻訳 / 必要なダウンロード / ポーランド語 / 日本語
  “翻訳”を使用するには、デバイスに言語をダウンロードする必要があります。…
  ダウンロードには数分かかることがあります。ダウンロードはバックグラウンドで継続します。
  ```
- **根拠2（原因の直接プローブ・実機 `EvalSixProbeTests.testP1/P2`）**:
  この実機での `LanguageAvailability.status` の実測値。
  ```
  en->ja=installed / es->ja=installed / ko->ja=installed / fr->ja=installed / pt->ja=installed /
  de->ja=installed / zh->ja=installed / tr->ja=installed / it->ja=installed / nl->ja=installed /
  ar->ja=supported(未ダウンロード) / pl->ja=supported(未ダウンロード) /
  ru->ja=supported(未ダウンロード) / th->ja=supported(未ダウンロード) / zxx->ja=unsupported
  ```
  英語向け（`->en`）もまったく同じ内訳（`ar` `pl` `ru` `th` が未ダウンロード）。
  同梱シードの prompt_001 には `ar` `pl` `ru` `th` が**各1件ずつ計4件**入っているので、
  31件を読み切るまでに必ず当たる。
- **推測（症状とは分けて書く）**: `Translator.isSupported(sourceCode:)` が
  `status != .unsupported` で判定しているため、`.supported`（＝この端末では**まだ
  ダウンロードされていない**）を `.installed` と同じ「翻訳できる」として扱い、そのまま
  `session.translate(_:)` を呼んでいる。Apple Translation はこのときOSのダウンロード要求
  シートを出し、利用者が応答するまで `translate(_:)` を返さない。
  `SessionRequestQueue` の30秒ジョブタイムアウト＋`session.cancel()` は、この状況では
  タイムラインの表示を回復させられていない（90秒観測して復帰なし）。
  直す方向は `.installed` と `.supported` を分けること。受け入れ条件4の文言（「初回のみ
  準備中の表示が出て完了後に読め」）に沿うなら `.supported` は
  `TranslationSession.prepareTranslation()` で明示的に取得してから翻訳する。
  取得しない方針を採るなら `.unavailable(permanent: false)` にしてその回答をスキップする
  （既読にはしない）。**どちらにせよ、OSにシートを出させてはいけない。**

### [2] 固着したとき、タイムラインが無言で閉じる／空白のまま残る（利用者が何が起きたか分からない）

- **再現手順**: [1] と同じ
- **期待**: 何が起きたか分かる表示が出るか、少なくともスキップして次が出る
- **実際**: 2パターンある。どちらも画面から理由が読み取れない
  - OSのシートが出るケース: タイムラインが**勝手に閉じて**今日のお題画面に戻る。
    利用者から見ると「読んでいたら急に画面が変わって、見覚えのないダウンロードの確認が出た」
  - シートが出ないケース（3回目）: タイムラインは開いたままだが、カードも読み切り表示も
    ローディング表示も無い**空白**になる（`timeline.close` はあるが `timeline.card.body`・
    `timeline.exhausted` はいずれも存在しない）
- **根拠**: `D01 固着時 buttons=["設定", "世界の回答を読む", "閉じる", "丸下矢印", "丸下矢印"]`（1つ目）、
  `D01 固着時 timeline.close=true … card=false like=false`（2つ目）
- **付随して起きること**: OSのシートには**投稿の言語名（「ポーランド語」）が出る**。
  spec.md 195行が禁じている「投稿言語のラベル」そのものが、結果として利用者の画面に出る。
  アプリ自身のUIには翻訳関連の表示は1つも無い（D04で確認済み）ので、これは [1] の副作用として扱う

## 改善提案（合否には影響しない）
- **[優先度 高]** 翻訳が1件も成立しない端末で回答が軒並みスキップされ、即「読み切り」になる。
  「いま読める回答がありません」に相当する状態を分けて出すと理由が伝わる（attempt 1 から継続）
- **[優先度 中]** `Translator.textCache` に上限が無い（attempt 1 から継続・未対応）
- **[優先度 中]** `-SameQFakeTranslate` はモデルのダウンロード状態（`.supported`）を再現できない。
  今回の [1] が疑似モードのUIテストを1本も落とさずに通ったのはこのため。
  `LanguageAvailability` を差し替え可能にして `.supported` を注入できるようにすると、
  同種の不具合を実機前に捕まえられる（attempt 2 の eval から継続）
- **[優先度 低]** 同梱シードに `ar` `pl` `ru` `th` が含まれているのは検証上むしろ有用なので残してよいが、
  「モデル未取得の言語ペアを必ず1件は踏む」ことを前提にした実機テストを1本置いておくと再発を防げる
