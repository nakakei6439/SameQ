# スプリント 04: 通報とブロック（F13 / F14 / F15）

## 受け入れ条件（spec.md 160〜166行から転記）
- [ ] タイムラインの回答から通報でき、理由を選んで送信すると完了表示が出て、その回答が自分の表示対象から即座に消える
- [ ] 通報した回答は、アプリを再起動しても再表示されない
- [ ] ブロックすると、そのユーザーの回答が以後1件も表示されない（同じお題内でスワイプを続けても出てこない）
- [ ] 設定画面にブロック中のユーザー一覧があり、解除するとそのユーザーの回答が再び表示対象に戻る
- [ ] 通報・ブロックしたことが相手に伝わる表示や通知が一切存在しない
- [ ] 通報・ブロックの操作後、タイムラインは次の回答へ自然に進み、操作前の位置で固まらない

## 実装方針
- `Model/Safety.swift` を新設し、`ReportReason`（政治的対立/宗教対立/差別/性的内容/犯罪助長/個人情報/その他）・`Report`・`BlockedAuthor` を定義。
- `PersistedState` を schemaVersion 3 にし、`reports` と `blockedAuthors` を追加（保存時に現在のバージョンへ揃える）。
- `LocalBackend.candidates(promptID:at:)` に「通報済みの投稿を除く」「ブロック中の著者を除く」を足す。
  他人の回答が0件（`.empty`）と、ブロック/通報で候補が尽きた（`.exhausted`）を区別する。
- タイムラインの上部に ⋯（`timeline.more`）を置き、シートで「通報→理由選択→送信→完了」「ブロック→確認→完了」を行う。
  送信の時点でデータ層から除外し、その場で次の1件を引く（シートを閉じると次の回答が出ている）。
- 設定画面（`Feature/Settings/SettingsView.swift`）を新設。今回はブロック一覧と解除のみ。
  一覧に出すのは絵文字とニックネームだけ（国・言語・本文・時刻は出さない）。
- ブロック時はその著者の回答の既読記録を落とす（解除したときに再び表示対象へ戻すため）。

## 影響範囲
- `candidates()` の条件追加はスプリント03の取得ルール（未読優先ランダム）に直結する。既存ユニットテスト10本で回帰を確認。
- タイムラインの操作追加でスプリント01の いいね／次へ の導線を壊さないこと。
- 設定画面への導線を今日のお題／お題待ちに足すため、スプリント02の「履歴導線が無い」担保を崩さないこと（設定に出すのはブロック一覧のみ）。
