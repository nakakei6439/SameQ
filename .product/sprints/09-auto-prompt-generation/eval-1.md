## 不合格の原因（これを直せば通る）

### [1] 本番相当の起動経路では、お題の自動生成が一度も発火しない。翌日にアプリを開いても前日と同じお題のまま

- **再現手順**:
  1. シミュレータへアプリを新規インストール
  2. `-SameQResetState -SameQDebugOverlay` のみを付けて起動（`-SameQScenario`・`-SameQSkipSeed`・`-SameQSeedOnly` はいずれも付けない = 通常のユーザーが行う操作そのもの）
  3. オンボーディングを完了し、今日のお題画面に到達 → お題文「今日、思わず笑ってしまったことは何ですか？」、デバッグオーバーレイ `prompt_001 ends in 93592s`（≒26時間）
  4. アプリを終了（`terminate`。アンインストールはしない＝同じインストールのまま）
  5. `-SameQResetState` を付けずに、`-SameQTimeOffsetMinutes 1440`（24時間後）だけ付けて再起動（＝「翌日にアプリを開く」の再現）
  6. 今日のお題画面のお題文とデバッグオーバーレイを確認
- **期待**: spec.md 246行「1日1回、新しいお題が自動で作られ、翌日にアプリを開くと前日と異なるお題が表示される」。手順5の時点で `prompt_yyyyMMdd` 形式の自動生成お題（`PromptCatalog.candidatePool` 由来のテキスト）に切り替わっているはず。
- **実際**: 手順6で確認したお題文は手順3と**完全に同一**（「今日、思わず笑ってしまったことは何ですか？」）。デバッグオーバーレイも `prompt_001 ends in 93597s`（≒26時間、手順3とほぼ同じ残り時間）のままで、`discarded` も 0 のまま変化なし。24時間進めても `prompt_001` が「たった今始まったばかり」であるかのように再構築され続けており、`PromptGenerator` による自動生成は一度も走っていない。
- **実測ログ**（evaluator が追加した一時UIテスト `EvalTempSprintNineRealWorldTests` の出力、`/tmp/sq_eval_realworld.log`）:
  ```
  day1_prompt_text=今日、思わず笑ってしまったことは何ですか？
  day1_overlay=now 13:46:53 · scenario live · prompt_001 ends in 93592s · ...
  day2_prompt_text=今日、思わず笑ってしまったことは何ですか？
  day2_overlay=now 13:46:58 · scenario live · prompt_001 ends in 93597s · ...
  same_text=true
  ```
- **根拠（コード、推測として記載）**:
  - `SameQ/Backend/SeedCatalog.swift` の `startDates(...)`（243〜277行）は、`scenario == .live` のとき常に `firstStart = reference.addingTimeInterval(-2 * 60 * 60)` としてシードのスケジュールを**起動のたびに動的に再構築**する。`reference` は毎回の「起動時の今」なので、何日後に起動しても `prompt_001` は常に「2時間前に始まったばかり」として作り直される。
  - `SameQ/Backend/PromptGenerator.swift` の `scheduleAlreadyCoversToday(schedule:reference:)`（197〜208行）は、`reference` の属する UTC 日の範囲とシードの `prompt_001` の期間が重なるかどうかで自動生成の要否を判定するが、上記の動的再構築により `prompt_001` の期間は常に「今」を含むため、この判定は**常に true**（＝シードがカバー済み）になり、`SeedCatalog.loadScheduleWithAutoGeneration`（117〜146行）は自動生成 (`PromptGenerator.generate`) を一度も呼ばない。
  - つまり `skipSeed: true`（`-SameQSkipSeed`）を付けない限り、`PromptGenerator` は本番の起動経路から実質的に到達不能。
  - `self-review.md` の「受け入れ条件の達成状況」表で条件1の根拠として挙げられているテストはいずれも `-SameQSkipSeed` 付き（`PromptGenerationTests.testGeneratorReturnsDifferentPromptForDifferentDays` はデータ層の単体呼び出し、`SprintNineAcceptanceTests.test03_skipSeedDifferentDaysMayDiffer` は `skipSeed: true`）であり、**本番相当の起動経路（シードあり・skipSeedなし）で「翌日に別のお題が出る」ことを確認しているテストが1つも存在しない**。self-review の「自分で見つけた弱点1」でもこの穴に薄々気づいていた記述があるが（「実時間では正常に切り替わるため問題ない」という推測）、今回の実機検証によりその推測は誤りであることが確認できた。

### 影響

`-SameQSkipSeed` 経由の `PromptGenerator` 単体ロジック自体（決定性・破棄記録・フォールバック・重複なし）は正しく実装されており、ユニットテスト18件・当該UIテスト2件（サニティチェックとして再実行）はいずれも成功している。問題は **SeedCatalog との統合部分**にある。「シードが常に『今日』を動的にカバーし続けるため、自動生成に処理が渡らない」という導線の欠落が原因であり、`PromptGenerator` 自体を直す必要はない。`SeedCatalog.startDates` の `.live` シナリオの相対スケジューリングと、`scheduleAlreadyCoversToday` の判定の組み合わせを見直す必要がある（例: シードの `prompt_001`/`prompt_002` に固定の絶対日程を持たせる、または一定日数が経過したらシードを自動生成へフェードアウトさせる設計に変える、など）。
