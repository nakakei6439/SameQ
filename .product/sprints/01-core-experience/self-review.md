## 自分で見つけた弱点

1. **Supabase に繋がっていない（ブロッカー）**
   クラウドプロジェクトが未作成で、URL と anon key を持っていない。推測の値を埋めるのは危険なので、
   アプリのデータ層は `Backend` プロトコル + 端末内実装（`LocalBackend`）で動かしている。
   テーブル定義・RLS・ビューは `supabase/migrations/20260817000001_init.sql` に先行して書いたが、
   **一度も適用・実行していない**（ローカル検証には Docker が必要で、この環境に Docker が無い）。
   したがって SQL の構文・RLS の妥当性は未検証。認証情報が用意でき次第、
   `BackendProvider.make()` を差し替える前提で、UI 層はプロトコルしか触っていない。
   この状態では「複数端末で同じお題を見る」「他人の投稿が本当に他人から来る」は検証できない。

2. **タイムラインの取得ルールは仮**
   起動ごとにシャッフルした配列を頭から出すだけ。既読管理（`viewed_posts`）は書き込んでおらず、
   タイムラインを閉じて開き直すと既に読んだ回答が再び出る。未読優先・ランダム1件取得はスプリント03の範囲なので、今回は入れていない。
   読み切ったときは「今日はここまで」を出して破綻しないようにしてある。

3. **お題の有効期間・投稿の寿命は未実装**
   `Prompt` は id と本文だけを持ち、開始/終了時刻を見ていない。お題待ち画面も無い（スプリント02）。
   SQL 側には `starts_at` / `ends_at` / `expires_at` を用意してある。

4. **文字数上限を140文字にした**
   F04 の「文字数カウンター付き」を満たすために上限が必要で、スプリント10に出てくる無料ユーザーの上限（140文字）に合わせた。
   超過分は入力時に切り詰める。Plus の長文はスプリント10。

5. **`-SameQRestState` ではなく `-SameQResetState` という Debug 限定の起動引数を製品コードに入れた**
   UIテストと再検証のため。Release ビルドでは `#if DEBUG` により存在しない。

6. **オンボーディングは「戻る」で前のステップに戻れる**
   仕様に明記は無いが、規約を読み直したい・絵文字を選び直したい場合に必要と判断した。
   アカウントは最後のステップまで作られないので、途中で戻っても何も残らない。

7. **見た目はモックアップに寄せたが、背景の水彩イラストは入れていない**
   「もう少しシンプルに」という要望を優先し、淡いグラデーション＋白い角丸カード＋緑のプライマリボタン＋丸ゴシック（`.rounded`）に留めた。
   タイムラインの操作は ✕（次へ）と ♥（いいね）の2つだけ。通報（!）はスプリント04で足す。
   いいね数・いいね一覧・タブバーはモックアップに描かれていたが、仕様と矛盾するので入れていない。

## 提案（今回はやらなかったこと）

- Supabase プロジェクトを作成し、`BackendProvider` に `SupabaseBackend`（匿名認証 + `world_timeline` ビュー）を足す。
  スプリント02以降の「複数端末で同じお題」「期限切れ」の検証は、実サーバーが無いと本当の意味では確認できない。
  **必要なもの: Supabase プロジェクトの URL と anon key。**
- 用意した SQL を `supabase db reset`（Docker 必要）または実プロジェクトに適用して、RLS が意図どおりか確認する。
- 設定画面（絵文字・ニックネーム変更）はスプリント11。それまで、選んだ絵文字を変える手段がアプリ内に無い。
- タイムラインのカードに戻る操作が無いことを明示する UI（スプリント03の範囲）。
