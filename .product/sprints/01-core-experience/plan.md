# スプリント 01: コア体験（設定→お題→投稿→世界タイムライン→いいね）

## 受け入れ条件（spec.md 107〜115行から転記）
- [ ] 初回起動で「コンセプト説明→利用規約同意→絵文字選択→ニックネーム入力（空のままでも進める）→通知許可」の順に進み、最後に今日のお題画面に到達する
- [ ] 利用規約に同意していない、または絵文字を1つも選んでいない状態では次へ進めない
- [ ] アプリを終了して再起動しても初回設定は再表示されず、選んだ絵文字とニックネームが保持されたまま今日のお題画面（回答済みならタイムライン）が開く
- [ ] そのお題に未回答の間は、他人の回答が1件も見えない（タイムラインへの導線が無い、またはロック表示になる）
- [ ] お題画面で本文を入力して投稿すると、投稿完了後に世界タイムラインが開き、自分以外のユーザーの回答が1件表示される
- [ ] タイムラインの各カードに、投稿者の絵文字・ニックネーム（未設定なら絵文字のみ）・回答本文が表示される
- [ ] スワイプすると別の回答へ切り替わり、自分自身の投稿は一度も表示されない
- [ ] いいねを押すと押下状態に変わり、他の投稿へ進んでからタイムラインを開き直しても押下状態が保たれる

## 実装方針
- XcodeGen（`project.yml`）で SwiftUI App の雛形を生成。iOS 18.0 Deployment Target、依存なし。
- データ層は `Backend` プロトコル1枚に集約し、今回は `LocalBackend`（Application Support 配下の JSON 永続化 + バンドル同梱のシードデータ）で実装する。
  Supabase クラウドプロジェクトの URL / anon key を持っていないため、実サーバー接続は行わない（ブロッカーとして記録）。
  スキーマは `supabase/migrations/` に SQL（RLS 込み）として先行定義する。
- 画面は `RootView` が状態（オンボーディング未完了 / 未回答 / 回答済み）で出し分ける。
  タイムラインは「回答済み」状態でしか到達できない構造にし、未回答時はビュー自体を生成しない。
- アカウントはオンボーディング最終ステップ完了時に**一括で**永続化する（途中終了で中途半端なアカウントを作らない）。

## 影響範囲
- 新規プロジェクトのため既存コードへの影響なし。
- `.gitignore` が `*.xcodeproj` を除外しているため、evaluator がビルドできるよう除外を解除する（`xcuserdata/` 等は引き続き除外）。
