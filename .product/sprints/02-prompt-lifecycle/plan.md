# スプリント 02: お題のライフサイクルと投稿の寿命（F08 / F09 / F10）

## 受け入れ条件（spec.md 126〜132行から転記）
- [ ] 有効なお題が無い時間帯はお題待ち画面が表示され、回答入力欄もタイムラインへの導線も存在しない
- [ ] お題の有効期間中に未回答で起動すると今日のお題画面が、回答済みで起動するとタイムラインが開く
- [ ] お題の終了時刻を過ぎると、そのお題の回答はタイムラインに1件も表示されなくなり、画面がお題待ち状態へ切り替わる
- [ ] 新しいお題が開始すると、前のお題に回答済みのアカウントでも再び未回答状態になり、今日のお題画面が表示される
- [ ] アプリ内のどこにも、自分の過去の投稿・過去のお題・いいねした投稿を一覧する導線が無い
- [ ] 期限切れの直前に投稿した回答も、お題の終了時刻を過ぎれば他ユーザーから見えなくなる

## 実装方針
- `Prompt` に `startsAt` / `endsAt`、`Post` に `expiresAt`（= お題の終了時刻）を持たせる（置いた前提2: 28時間固定・常に1つだけ有効）。
- `Backend.activePrompt()` を `promptState() -> .active(Prompt) / .waiting(nextStartsAt:)` に置き換え、期限切れ投稿は `timelinePosts` / `myPost` から除外する。
- 「今」は `AppClock` に集約し、`LaunchOptions`（Debug 限定の起動引数）で**シナリオ**と時刻オフセットを切り替えられるようにする。シナリオ: `live` / `expiring`（数分後に終了→隙間→次のお題開始）/ `expired`（既に終了）/ `upcoming`（未開始）。
- `AppSession` に `.waiting` 画面を足し、1秒ごとの再判定（＋前面復帰時）で、画面を開いたままでも期限をまたいで切り替わるようにする。タイムライン表示中に期限が切れたら閉じてお題待ちへ。
- 新規 `WaitingPromptView`（入力欄・タイムライン導線なし）。履歴導線は今回も一切追加しない。

## 影響範囲
- `Backend` プロトコル変更 → `LocalBackend` / `AppSession` / `RootView` / `TodayPromptView` が連鎖。
- 同梱シード（`SeedData.json`）を「お題2件＋各お題の回答」構造へ変更。`supabase/` の SQL も追随（未適用のまま）。
- スプリント01の UI テスト（`SprintOneAcceptanceTests`）は既定シナリオ `live` で従来どおり通る必要がある。
