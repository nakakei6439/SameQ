=== 根本原因（ソース読み合わせ） ===
SameQ/Backend/SupabaseBackend.swift の init() 内で
  let tokenBox = TokenBox(initial: store.load().supabaseAuth?.accessToken)
  self.client = SupabaseClient(session: session, tokenProvider: { tokenBox.value }, ...)
という形で、SupabaseClientが使うアクセストークンは `tokenBox.value` から都度取得する設計。
しかし `tokenBox.value = ...` への代入はファイル全体でこの2箇所のみ:
  - options.resetsState のとき tokenBox.value = nil
  - state.supabaseAuth != nil && options.resetsState のとき tokenBox.value = nil
createAnonymousUser(emoji:nickname:) は client.anonymousSignUp() で新しい
access_token を取得する（`auth.accessToken`）が、その値を tokenBox に反映する
コードがどこにも無い。そのため直後の
  client.insertVoid(table: "users", body: UserInsert(...))
は tokenBox.value（= nil、まだ更新されていない）のまま送信され、
Authorization ヘッダーが欠落 or 無効な状態で PostgREST に届き 401 を受け取る。
SupabaseClient.validate(response:data:) は 401 を無条件で
SupabaseError.unauthorized（「セッションが切れました。もう一度やり直してください。」）
に変換するだけで、リフレッシュや再試行のロジックは無い。
`state.user` は insertVoid成功後（134行目以降）にしかセットされないため、
このエラーが起きると `next.user = user` / `store.save(next)` にも到達せず、
アカウント作成は一切完了しない。ユーザーが「OK」を押して再度「あとで設定する」を
押しても、毎回 client.anonymousSignUp() から新しいUUIDでやり直すだけで、
同じ理由で再び401になる（実際に2回再現、いずれも同じ失敗）。
