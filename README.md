# SameQ

世界中の知らない誰かと、同じ問いに答えるだけのSNS。

1日1回、世界共通のお題が届く。ただし通知がいつ来るかは分からない。
自分が答えて初めて、世界の誰かの答えを1件ずつ見られるようになる。
相手が何語で書いていても、本文もニックネームも最初から自分の言語・文字体系で表示される。

フォローも検索もランキングも会話もない。その日の言葉は消え、
「世界のどこかの知らない誰かも、こんなことを考えているんや」という感覚だけが残る。

## 1.0.2 (7)（2026-09-07 App Store 再提出）

再提出した **1.0.2 (6)** が、iPad Air 11-inch (M3) での審査で 2 件の指摘を受けた。

### Guideline 2.1(a) — 他ユーザーの投稿を確認できない

レビュアーがアプリに入っても、他ユーザーの回答が 1 件も表示されず機能を確認できなかった。

- 原因: `world_timeline`（他人の回答の唯一の入口）は「自分がそのお題に回答済みで
  なければ 0 件」というアンサーファーストを DB で強制している。加えて本番に恒久的な
  サンプル投稿の仕組みが無く、実ユーザーが少ない日はその日の回答が事実上 0 件になる。
- 対応:
  - **`ensure_official_answers()` を追加**（`supabase/migrations/20260905000001〜3`）。
    `ensure_todays_prompt()` と同じ「気づいたクライアントが自己修復する」パターンで、
    今日のお題に対し「SameQ運営」名義のアカウント 5 件の回答を冪等に投入する。
    お題は日次でローテーションするため一度きりの手動シードでは足りず、毎日自動で
    最低 5 件が並ぶ仕組みにした。実ユーザーの投稿が増えれば自然に埋もれる。
  - **`SupabaseBackend.timelinePosts` の SELECT 漏れを修正**。`world_timeline` から
    `body_language` を取得しておらず全投稿が言語 "und" 扱いになり、端末言語と同じ
    投稿でも端末内翻訳が走っていた。翻訳が使えない環境（シミュレータ・モデル未DL・
    オフライン）で他人の回答が無言でスキップされる経路を塞いだ。
- これはアプリの中核体験（回答すると誰かの回答が読める）の底上げでもある。

### Guideline 2.1(b) — In-App Purchase が審査未提出

アプリに「Plus」が表示されているのに、サブスクリプション
`com.nakakei6439.SameQ.plus.monthly` が `MISSING_METADATA` のままで審査に出せなかった。

- 対応（App Store Connect、コード変更なし）: App Review 用スクリーンショットを
  アップロードし、サブスクリプショングループのローカライズ（ja / en-US）を追加。
  状態が **READY_TO_SUBMIT** になり、1.0.2 (7) のバイナリと同時に審査へ送る。

### バージョン

匿名アカウント作成、1日1回世界共通で届くお題への回答、世界タイムライン、いいね・通報・ブロック、
ランダム通知、投稿本文とお題の自動翻訳、ニックネームの音写表示、通報・BAN・投稿頻度制限・
スパム対策のサーバー側判定、Plus（RevenueCatによる月額課金・1ヶ月無料トライアル・長文投稿と
文字装飾）、統合ヘッダー・ハンバーガーメニュー・運営お知らせ（日本語・英語の言語別配信）まで、
一通りの機能が本番のSupabaseバックエンドに接続した状態で動く。

初回設定 → 今日のお題 → 回答投稿 → 世界タイムライン → いいね が動き、
お題の有効期間（28時間・常に1つだけ有効）、有効なお題が無い時間帯の**お題待ち画面**、
投稿の表示期限（お題の終了時刻に揃える）が効く。

世界タイムラインは「同一お題／自分以外／表示期限内／BAN外」の回答から**未読だけをランダムに1件**引く。
出した回答はその場で既読として端末に記録するので、スワイプし続けても、アプリを再起動しても
同じ回答は二度と出てこない。読み尽くしたら「今は新しい回答がありません」、
自分の回答しか無ければ「まだ誰も答えていません」を表示する。前の回答へ戻る操作は無い。

不快な回答は、タイムライン右上の ⋯ から **通報**（理由を選んで送信）と **ブロック** ができる。
通報した回答は即座に自分の表示対象から消え、ブロックした人の回答は以後1件も出てこない。
どちらも相手には何も伝わらない。ブロックは設定（右上の歯車）の一覧からいつでも解除でき、
解除するとその人の回答は再び表示対象に戻る。

投稿は1つのお題につき1回だけ。直前の自分の投稿と全く同じ本文は別のお題にも投稿できず、
空白・改行のみや同じ文字の過剰な繰り返しも拒否される。いいね・通報を短時間に繰り返すと
一時的に制限され、その旨が画面に表示される（制限メッセージは日本語・英語を併記）。
運営がBAN状態にしたアカウントは起動すると専用の画面だけが表示され、お題にもタイムラインにも
入れない。BANされたユーザーの回答は他のユーザーのタイムラインに一切表示されない。

投稿本文とお題は、Apple Translation Framework だけを使って端末言語へ自動翻訳して表示する
（外部翻訳APIは使わず、翻訳のために本文をサーバーへ送ることもない）。翻訳ボタン・原文表示・
「翻訳済み」表示は一切無く、全員が最初から自分の言葉で話しているように見える。端末が翻訳できない
言語の回答はタイムラインに出さずスキップする。翻訳が確定するまでは「準備中…」を表示し、
原文が一瞬見えてから翻訳に差し替わる「ちらつき」を防いでいる。端末の言語設定は起動時に一度だけ
読むため、設定を変えたら**アプリを再起動**すると新しい言語で表示される。

### 動かす

```bash
open SameQ.xcodeproj      # 外部パッケージ依存なし。そのままビルド・実行できる

# 受け入れ条件の自動確認（ユニット200本超 + UIテスト100本超。スプリントが増えるたびに増加する）
xcodebuild -project SameQ.xcodeproj -scheme SameQ \
  -destination 'platform=iOS Simulator,name=iPhone 17' test
```

初回設定からやり直したいときは、アプリを削除するか、Debug ビルドに起動引数 `-SameQResetState` を付ける。

### お題の有効期間を検証する（Debug ビルド限定の起動引数）

実時間で28時間待たずに切り替わりを確認するための引数。Release ビルドでは無効。

| 引数 | 意味 |
|---|---|
| `-SameQScenario live` | 既定。お題が有効期間の途中（残り約26時間） |
| `-SameQScenario expiring` | 現在のお題がまもなく終了 → 空白（お題待ち）→ 次のお題が開始 |
| `-SameQScenario expired` | お題は終了済み、次はまだ先（お題待ち） |
| `-SameQScenario upcoming` | お題がまだ開始していない（お題待ち） |
| `-SameQExpirySeconds 120` | `expiring` で終了までの秒数（既定 180） |
| `-SameQGapSeconds 60` | `expiring` で終了から次の開始までの秒数（既定 180） |
| `-SameQTimeOffsetMinutes 90` | アプリが認識する「今」を前後にずらす |
| `-SameQDebugOverlay` | 画面下に現在時刻・お題ID・残り秒数・回答/既読/いいねの件数を表示 |

### タイムラインの取得ルールと既読を検証する（Debug ビルド限定の起動引数）

| 引数 | 意味 |
|---|---|
| `-SameQAnswerCount 0` | 自分以外の回答を0件にする（＝自分の1件しか無い状態。空状態の確認用） |
| `-SameQAnswerCount 1` | 自分以外の回答を1件にする |
| `-SameQAnswerCount 120` | 自分以外の回答を120件にする（大量ケース。本文に `#1-76` のような通し番号が入る） |
| `-SameQResetViewed` | 既読の記録だけを消す。アカウント・自分の回答・いいねは残る |

引数を付けない場合は同梱シードのまま（`prompt_001` に22件、`prompt_002` に12件）なので、
20回スワイプして重複が無いことはそのままでも確認できる。

`-SameQDebugOverlay` を付けると、画面下に `answers`（いま表示しうる回答の数）・`viewed`（既読）・
`liked`・`reported`（通報した数）・`blocked`（ブロック中の人数）が出る。
通報・ブロックの効き方はここで数字としても追える。

`-SameQAnswerCount` で機械的に作る回答は、**お題をまたいで同じ投稿者**になる
（1つのお題には1人1件のまま）。ブロックした人が次のお題にも出てこないことを確認できる。

### BAN・投稿頻度制限・スパム対策を検証する（Debug ビルド限定の起動引数）

BANは運営がサーバー側で切り替える運用のため、アプリ内にBANを切り替えるUIは無い。
検証用に起動引数で模擬する。

| 引数 | 意味 |
|---|---|
| `-SameQBanned` | 自分のアカウントがBAN状態であるかのように起動する。専用の「利用できない」画面だけが出て、今日のお題・タイムラインには入れない |
| `-SameQRateLimitTestMode` | いいね・通報の連打制限の閾値を短時間で確認できる値に縮める（いいね30秒3回・通報40秒2回、既定はいいね15秒8回・通報30秒4回） |

同梱シード（`SeedData.json`）には、BANされた投稿者の回答を1件混ぜてある
（`bannedAuthorIDs` に登録された投稿者。既存の22件の後ろに追加してあるので、
`-SameQAnswerCount` を使う既存の検証手順には影響しない）。引数なしで起動して
タイムラインを最後まで読み切っても、この投稿者の回答は一度も表示されない。

1つのお題への投稿は1回だけで、直前の自分の投稿と全く同じ本文は別のお題にも投稿できない
（投稿完了後は再送信できないよう画面側でも守られている）。空白・改行のみの投稿や、
同じ文字を並べただけの投稿（例:「あああああああ」）も拒否される。これらの制限メッセージは
すべて日本語行＋英語行を併記して表示する。

### 翻訳を検証する

`-SameQAnswerCount` を付けずに起動すると、同梱シード（多言語）のまま翻訳が確認できる。
`-SameQAnswerCount` を付けると機械生成の日本語のみの回答になり、翻訳を挟まない
（F11〜F17の検証用モードのため）。

端末（シミュレータ）の設定アプリで言語を日本語／英語／韓国語などに切り替えたあと、
**アプリを再起動**すると、その言語でお題・回答が表示される（アプリ内に言語切り替えは無い）。

### 構成

| パス | 中身 |
|---|---|
| `project.yml` | XcodeGen のプロジェクト定義（`SameQ.xcodeproj` は生成物だがコミットしてある） |
| `SameQ/Backend/` | データ層。`Backend` プロトコル、端末内実装 `LocalBackend`、お題の日程（`PromptSchedule` / `SeedCatalog`）、検証用の起動引数（`LaunchOptions`）、端末内翻訳（`Translator`） |
| `SameQ/App/TranslationHostView.swift` | `Translator` に `TranslationSession` を供給する常駐の不可視ビュー |
| `SameQ/Feature/` | 画面（Onboarding / Waiting / Today / Timeline / Settings） |
| `SameQ/Resources/SeedData.json` | お題2件と、それぞれへの世界の回答（23件 / 12件、18言語＋BANされた投稿者1件） |
| `SameQTests/` | お題の有効期間・投稿の表示期限・タイムラインの取得ルールと既読・通報とブロック・BAN/連打制限/スパム対策のユニットテスト |
| `SameQUITests/` | 受け入れ条件をなぞる UI テスト |
| `supabase/migrations/` | users / prompts / posts / likes / viewed_posts / reports / blocks / announcements と RLS・自己修復RPC等の定義 |
| `docs/HARNESS.md` | planner → generator → evaluator ハーネスとオートループの設計 |

アプリは本番の Supabase（`SupabaseBackend`）に接続して動く。`LocalBackend`（端末内完結の実装）は
Debug ビルドの起動引数 `-SameQUseLocalBackend` を付けたときだけ使われる、オフライン開発用の
経路として残している。

## 開発フロー

このリポジトリは planner → generator → evaluator のハーネスで開発される。

1. **planner**: 短いアイデアを製品仕様書（`.product/spec.md`）に展開
2. **generator**: 仕様書のスプリントを1つずつ実装
3. **evaluator**: 実装をシミュレータ/実機・ブラウザで実際に操作して検証。必須基準を1つでも満たさなければ不合格とし、generatorが修正して再評価

詳しい設計は [`docs/HARNESS.md`](docs/HARNESS.md) を参照。

進捗の詳細は [`PROGRESS.md`](PROGRESS.md) を参照。
